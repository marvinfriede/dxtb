## Reconciliation and ownership

Current upstream main already contains the important v0.7 work: composite
AtomicC6 evaluation, transform-aware batching, current tad-mctc coordination
number and safe-arithmetic APIs, and differentiable zero-valued `s9` handling.
The older U1 patch's edits to `model/c6.py`, weights, batching and coordination
numbers were therefore not replayed. The current main implementation and its
existing tests are retained.

The remaining dependency defect is metadata: main required
`tad-mctc==0.9.0`, while dxtb requires `==0.9.1`. The candidate changes only
that exact pin in `setup.cfg` and `environment.yaml` to `==0.9.1`; no broader
compatibility range is claimed. Direct upstream tests run against mctc 0.9.1
without importing dxtb or using its shim.

The current upstream dispersion API accepts a `Structure`, element tables and
new cutoff configuration. dxtb's established core stores independent
`setup_numbers` and `component_numbers`, along with captured per-atom/per-pair
`rvdw` and `r4r2` arrays. Reconstructing element tables from those values
changed a real legacy D3 result, so the candidate adds the narrow upstream
`dispersion_with_atom_values` entrypoint. It passes the captured arrays into
the same upstream two- and three-body kernels. It adds no D3 formula. dxtb
adapts only its D3 boundary, restores its established CN cutoff 25 and
dispersion cutoffs 50/50, and retains explicit `chunk_size` deprecation
behavior. The v0.6 call path remains available while v0.6 is the intentional
legacy profile.

## Evidence

Primary environment: Python 3.14.8, PyTorch 2.14.1+cpu,
tad-mctc 0.9.1, tad-dftd3 candidate 0.7.0, tad-dftd4 0.8.0,
tad-multicharge 0.7.0, PySCF 2.14.0 and tad-libcint 0.3.0. CUDA was
unavailable.

The v0.6.0 public GFN1 jacfwd characterization reproduced the missing custom
`AtomicC6.jvp` error before candidate integration. With the current-main
candidate wheel installed, the upstream focused suite passed **165 tests**:

```text

  test/test_model/test_c6.py test/test_grad/test_transforms.py \
  test/test_disp/test_dftd3.py test/test_grad/test_pos.py \
  test/test_grad/test_param.py test/test_disp/test_atom_values_compat.py \
  test/test_grad/test_third_order_accuracy.py
```

The suite includes s9-zero reverse/forward/vmap transform cases already in
main, D3 energies, derivatives, and the new adapter and third-order checks.
The third directional derivative on SiH4 was `5.777086688910111e-05` by AD
and `5.7770866838356524e-05` by a five-point finite difference of the Hessian:
absolute error `5.07e-14`, relative error `8.78e-10`. The adapter regression
compares element-table and captured-array paths for SiH4 and PbH4-BiH3, both
single and packed, including position gradients.

The final candidate wheel was installed by pip's normal dependency resolver in
a fresh Python 3.14 virtual environment, using the CPU PyTorch index and
PyPI. Resolution installed tad-mctc 0.9.1 and torch 2.14.1+cpu, with no
tad-dftd4 or dxtb compatibility shim. Direct import and an H2O D3 energy,

`tad-mctc==0.9.1` and `torch>=2.4,<3`. The clean venv's `pip check` reports
