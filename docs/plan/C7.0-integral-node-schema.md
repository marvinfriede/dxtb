# C7 integral and Hamiltonian Node schema and implementation record

Status: **C7.0 preflight and C7.1 PyTorch integral migration complete; C7
remains partial.** C7.0 established the schema and C7.1 promotes the
PairPlan/PyTorch setup Nodes into the exact single-System production path.
Physical kernels and existing Calculator drivers, integral containers, packed
routes, and compatibility adapters remain in use.

## C7.0 baseline evidence

The requested primary baseline selection covered pure evaluation, pure
multipoles, transforms, parameter gradients, matrix validation, PyTorch and
libcint driver tests, basis setup, and pure H0. On the accepted base, it
reported **152 passed, 1 skipped, 1 failed**. The failure was
`test_exponent_gradient_matches_fd[gfn2-LiH]`; it reproduced in isolation on
the same base with a NaN H0 matrix reaching `storch.eighb()` and a
`torch.linalg.eigh` convergence error. This is a baseline failure, not a C7
change. GFN1 LiH/H2O exponent-gradient rows passed in the combined selection.
No references or tolerances were changed.

Existing PyTorch pure-evaluation tests exercise reverse-mode position
derivatives through third order, `jvp`, `jacfwd`, and `vmap` for overlap and
multipoles. Pure H0 history tests passed for GFN0, GFN1, and GFN2 in the
baseline selection. The proof test adds exact overlap matrix and position
derivative equivalence with the Node-shaped PairPlan, plus an active basis
parameter gradient through `element.H.slater`. Libcint remains an eager,
reference, and supported analytical-gradient backend; this package makes no
claim that its external wrappers support `torch.func` transforms.

The C7.0 test-local proof schema checked pytree flatten/unflatten, dynamic leaves,
integer-preserving dtype conversion, floating conversion, meta-device
structural conversion for the PyTorch schema, compatible setup stacking, a
vmap probe over stacked structural data, one optional backend subtree, and
the GFN0/GFN1/GFN2 H0 callable descriptors. It is an executable design proof,
not a production setup conversion.

## C7.1 production evidence

`PytorchIntegralSetupNode`, `PairPlanNode`, and `PairClassNode` are registered
production Nodes. The exact single-System PyTorch path owns the Node and
reuses its captured plan for overlap, dipole, and quadrupole evaluation. The
Node uses `CoreIndexData` for shell-to-atom and orbital-to-shell expansion.
Setup conversion copies structural maps, pair indices, and pair weights to
isolate the System from mutable legacy setup objects; ordered exponent and
coefficient tensor references remain the original parameter tensors so their
autograd graph is preserved. Direct `setup_integrals()` and legacy Calculator
drivers retain `PytorchIntegralSetup` and the mutable `PairPlan` compatibility
route. Libcint continues to use its existing dataclass setup.

Production tests compare raw overlap/dipole/quadrupole values, normalized and
shifted matrices, H0, occupations, normalization values, and GFN1/GFN2 total
energies against the legacy setup for H2, LiH, and H2O. Derivative comparisons
cover position gradients through third order, basis-parameter and mixed
derivatives, JVP, jacfwd, jacrev, geometry vmap, and compatible stacked-setup
vmap. Pair selection, chunking, checkpointing, fullgraph compile, structural
snapshot isolation, plan reuse, and legacy setup conversion remain covered. The
focused selection (`test_c7_schema_proof.py`, `test_pure_evaluation.py`, and
`test_pytorch_setup_node.py`) passed **44 tests, 1 skipped** in each approved
environment: Python 3.10.22/PyTorch 2.6.0, Python 3.11.15/PyTorch 2.8.0,
Python 3.12.10/PyTorch 2.11.0, Python 3.12.10/PyTorch 2.13.0, and Python
3.14.8/PyTorch 2.14.1. TorchScript deprecation/future warnings appeared on the
2.11.0, 2.13.0, and 2.14.1 environments. CUDA was not available for this
validation.

The broader integral/basis/pure-H0 selection reported **733 passed, 4 skipped,
7 failed** on the candidate. Each of those seven exact node IDs was rerun on
the C7.1 base and failed there as well. Five LiH rows terminate in the
existing GFN2 SCF path with `torch.linalg.eigh` convergence errors. The two
SiH4 force rows fail the unchanged `1e-11` reference comparison with about
`1e-9` residual force components. The GFN2 LiH exponent-gradient failure was
already recorded by C7.0. These matched-base failures do not establish a
C7.1 regression; no tolerance or reference values changed.

The canonical four-target E0 eigensolver selection reported **23 passed,
1 failed** on the candidate. `eigensolver.small_gap_aufbau:order2` also failed
when run alone on both the exact C7.1 base and candidate with the same
`GradcheckError` class, though the mismatching Jacobian input index differed
(base input 1, candidate input 0). This matches the already tracked
intermittent small-gap observation and is not classified as a C7.1 regression.
The three focused functional-map/parameter-graph/history controls passed. The
non-slow E3.1b implicit-root selection passed (29 tests). E3.0, E3.1a, and
the slow NO2 implicit row were not rerun; no SCF or implicit-root code changed,
and full E3 remains blocked by E1.3.

A small setup/evaluation timing characterization used H2O/GFN2, float64 CPU,
Python 3.14.8/PyTorch 2.14.1 on x86_64. After two warmups, ten timed samples
were summarized by median/min/max in milliseconds: full `setup_integrals`
0.867/0.852/1.116; `prepare` pair-plan construction 0.211/0.208/0.224; Node
conversion 0.174/0.172/0.199; repeated overlap 1.993/1.970/2.056; and one
overlap+dipole+quadrupole set 7.957/7.858/8.223. These small-fixture CPU
measurements characterize cost only and do not support a speedup claim.

## Package split

| Package | Scope | Acceptance boundary |
| --- | --- | --- |
| **C7.1** | PyTorch integral setup and PairPlan Nodes — complete | Production exact single-System setup is a `PytorchIntegralSetupNode`, uses ordered immutable pair Nodes and `CoreIndexData`, and passes parity, setup-ownership, derivative, transform, screening, compile, and five-environment focused controls. |
| **C7.2** | H0 setup and Hamiltonian structural data | Add H0-specific index Node and explicit built-in CN descriptors; retain every gathered H0 tensor and nested EEQModel as children; compare GFN0/GFN1/GFN2 matrices, occupations, geometry/parameter/mixed derivatives; retain custom callable CN on a documented legacy route. |
| **C7.3** | libcint structural setup and adapters | Represent BasisSetup fields and only required shell maps as Nodes; preserve `force_cpu`, exact device movement, and external-call-local wrappers; keep packed/Calculator compatibility; validate existing eager/reference and supported analytical controls without imposing `vmap` or high-order transform requirements. |
| **C7.4** | IntegralMatrices/output integration, only if needed | Decide whether an API must return `IntegralMatrices` directly through transforms. If not, keep its current validated frozen dataclass. Include full C7 acceptance review only when 7.1–7.3 close. |

Legacy Calculator drivers, `Integrals`/`IntegralContainer`, `DriverManager`,
packed setup routes, and external libcint wrappers remain legacy-owned. Their
retirement is coordinated with E6broute and E4.6 compatibility policy. C7.0
does not complete C7, B3b, E1.3, or any legacy-driver retirement.
