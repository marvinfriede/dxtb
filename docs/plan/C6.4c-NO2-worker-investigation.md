Status: diagnostic run completed, cause unresolved. A worker-mode
third-derivative NaN was reported on the candidate, while serial execution
was reported to pass. The original failure was not reproduced under the
matched runs below. No production or test change was justified. This report
does not classify the failure as fixed, environmental, or inherited.

## D4SC provenance and ordering

In all instrumented NO2 cases, the selected per-call list contained the exact
`system.d4sc_interaction` object and
`interaction_data.d4sc_setup is system.d4sc_setup` was true on both base and
candidate. The setup was a `D4SCCoreSetup` containing `D4Model`, `model_wf=6`,
`model_rc6` shape `(3, 3, 7, 7)` and sum `3568.897504438012`, with empty
`model_extra`. Functional setup used the corresponding compatibility view.

Uncontrolled fresh-process probes observed different interaction and
functional-entry orders, including on repeated candidate launches with fixed
`PYTHONHASHSEED=0`. This is consistent with the existing
`ComponentList.__init__()` set comprehension in
`src/dxtb/_src/components/list.py:145`; object identity hashes are not
stabilized by `PYTHONHASHSEED`. The matched diagnostic run had the same order
on base and candidate. In a temporary diagnostic-only experiment, component
lists preserved insertion order; the NO2 test passed on both SHAs under
`-n logical`. The same insertion-order rule produced byte-identical prepared
SCF tensor-tree fingerprints on base and candidate, including D4SC `model_wf`
and `model_rc6`. Since the failure was not reproduced with either ordering,
ordering is a confirmed independent C6 structural follow-up, consistent with
the roadmap requirement that component lists keep order. It is not a
demonstrated cause of the reported NaN. No permanent `ComponentList` change is
included here.

The C6.4b source change selects setup authority after resolving the list. In
this NO2 test the exact System-owned component is selected, so the authority
check retains the same setup as the base. It does not reorder components or
change the D4SC setup/model values for this case.
