## Dependency and import contract

dxtb keeps `tad-mctc==0.9.1`. The official D3 0.7.0 wheel metadata requires
`tad-mctc==0.8.0`, so the two exact requirements cannot be resolved together
by pip. The controlled test setup installs dxtb's requirements first, then
installs the official D3 wheel with:

```sh
python -m pip install --no-deps --index-url https://pypi.org/simple tad-dftd3==0.7.0
```

This workflow does not make `pip check` clean: it reports that D3 requires
mctc 0.8.0 while 0.9.1 is installed. Other pre-existing tad-dftd4,
tad-multicharge, libcint, and NumPy metadata conflicts are reported
separately. The dxtb package requirement for mctc is not weakened.

The official wheel imports after dxtb activates
`dxtb._src.mctc_shim`. The released package imports
`tad_mctc.autograd.is_batched`, which mctc 0.9.1 no longer exports. The
shim adds only this absent name and maps it to `is_vmapped`, whose traversal
detects vmap wrappers beneath reverse-mode wrappers. It does not override an
existing API. Ordinary tensors and JVP-only tensors are not classified as
vmapped; nested `vmap(jacrev(...))` detects the batch layer. The official
AtomicC6 code has its own wrapper-stack fallback on the supported PyTorch
versions; the shim also satisfies its released import contract.

The D3 adapter calls the official `model.atomic_c6`,
`dispersion2`, and `dispersion3` implementations. It retains dxtb's
captured reference tables, per-atom and pair radii, CN cutoff, dispersion
cutoff, and distinct number inputs. It does not copy D3 formulas.

The D3 0.7 `atomic_c6` signature has no `chunk_size`. A non-`None`
legacy value still emits a `DeprecationWarning` explaining that the grouped
algorithm does not apply the requested chunk size. The earlier bounded
chunking memory behavior is not recreated; very large systems should account
for the new grouped-C6 algorithm's memory characteristics.

## Differentiable zero s9

The released `dispersion()` wrapper branches on the numerical value of
`s9`, which drops the ATM derivative when a trainable tensor is exactly zero.
dxtb now has one internal compatibility evaluator used by both
`DispersionD3.get_energy()` and `dispersion_d3_energy()`. It obtains the
two-body atom-resolved contribution from official `dispersion2` and adds the
official `dispersion3` ATM contribution whenever `s9` is tensor-valued.
This retains derivatives at tensor-valued zero without reading tensor values
in Python. A literal Python zero can skip the cubic-cost ATM work. No
physical formula, damping, cutoff, reference table, or energy partition was
changed.

On GFN1/H2O with a Model-owned differentiable `s9=0`, reverse
`dE/ds9` is finite and nonzero. It matches a central finite difference with
step `1e-4` at `atol=1e-10, rtol=1e-6`. The legacy cache route and exact
System-owned setup route produce the same derivative. Public GFN1 third
directional derivative accuracy remains covered by the E6a.4 five-point
finite-difference test.

The separate C8b Model parameter-tree and E6bcompat-policy controls passed
60 tests in Python 3.14/Torch 2.14.1. A full-tree non-slow attempt using
`-m 'not slow and not large and not baseline' -n logical --dist worksteal`
reached 99% but stalled while shutting down and was interrupted; it emitted
failure markers without a final summary. That run is not counted as passing
and is not used to classify individual failures. The focused D3 and E6a
selections completed in all five environments.

One single-threaded Python 3.14/Torch 2.14.1 CPU microbenchmark measured the
adapter at 20, 50 and 100 atoms. With a non-trainable zero `s9`, ATM is
skipped and evaluation took 0.0006, 0.0008 and 0.0032 seconds. With
trainable `s9=0`, where ATM evaluation is required to produce `dE/ds9`,
evaluation took 0.0021, 0.0210 and 0.1303 seconds. These are single-call
timings, not a broad performance claim; the necessary differentiable ATM
path grows quickly with system size. The ordinary constant-zero path retains
the inexpensive skip.

## Limits and status

The tests establish official-release numerical and transform behavior for
the covered configurations; they do not certify all dxtb packages or every
system size. The package-metadata conflict remains real and requires the
documented controlled installation. E1.3 remains open pending completion of
its broader supported component and derivative matrix and the project's
dependency/release policy decision. E6a remains open for its own remaining
acceptance gates. No C8b, E6b, E7, or E4.6 ownership changed.

The local upstream candidate checkout, candidate branch, and candidate wheel
were removed after official-only validation. The named remote branch was
verified at `814f55795b1fe17cb07aba36bb81e53c004ad7b2`, deleted as requested,
and then verified absent. Upstream main, release tags, and source were not
modified. The old patch file remains only as historical evidence referenced
by the U1 report.
