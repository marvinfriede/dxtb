# E1.3-L2a — Official D3 integration hardening

Status: source audit and cutoff/derivative regressions implemented. The
broader non-slow selection completed in deterministic groups; SCF/C60
fixtures make it substantially slower than its marker suggests.

Starting SHA: `7fb99bb27ed493d98c5a850af322bcae4f4e0573`.

## Dependency identity and import boundary

All tested environments use the official PyPI wheel
`tad-dftd3==0.7.0`, SHA-256
`44bb0ddec5fdce42f4c50f0f8270a52a996390a25db827ef2e370110bd1bde7e`, with
`tad-mctc==0.9.1`. No candidate wheel, upstream checkout, source injection,
or modified site-packages were used. The official wheel metadata pins
`tad-mctc==0.8.0`; the controlled `--no-deps` installation is therefore
required and `pip check` is expected to report that conflict. The runtime
shim does not repair package metadata.

The local shim adds `tad_mctc.autograd.is_batched` only when that name is
missing, mapping it to mctc 0.9.1's `is_vmapped`. It runs during `import dxtb`
before a later D3 import. It does not overwrite a valid external symbol.
`import dxtb; import tad_dftd3` succeeds; direct `import tad_dftd3` without
the dxtb-owned shim fails because the released package imports the removed
name. This direct-import limitation is part of the documented runtime
contract for this metadata-incompatible installation.

## Adapter audit

There remains one local integration path: both the legacy
`DispersionD3.get_energy()` and pure `dispersion_d3_energy()` obtain C6 and
reference weights from tad-dftd3 and call its `dispersion2` and `dispersion3`
kernels through the shared internal evaluator. The adapter preserves captured
atomic numbers, reference tables, per-atom/pair radius data, D3 parameters,
atom-resolved partitioning, and tensor device/dtype. It introduces no
geometry cache or persistent mutation. Tests compare the two entrypoints and
exercise repeated calls, setup ownership, position gradients, parameter
gradients, and transforms.

The official `atomic_c6` API no longer accepts `chunk_size`. A non-`None`
legacy value raises the existing explicit `DeprecationWarning`; `None` does
not warn. The option is not silently applied, and the previous chunking
algorithm is not recreated. Existing regressions cover warning and output
behavior at both public D3 entrypoints.

## Cutoff contract

The historical dxtb adapter has a coordination-number cutoff of 40 bohr and
a shared 50-bohr dispersion cutoff; the existing scalar D3 cache cutoff
continues to control coordination construction. The released
`tad_dftd3.Cutoff()` defaults are CN=40, disp2=60, disp3=40. Changing dxtb
to those new dispersion defaults would change the established numerical
contract. The adapter therefore passes its captured legacy 50-bohr
dispersion limit to both official terms. It does not claim that dxtb exposes
independent two- and three-body cutoffs.

A nonzero-ATM H2O geometry with interatomic distance 45 bohr verifies local
atom-resolved energy and position-gradient parity with official
`dispersion(..., Cutoff(disp2=50, disp3=50))`. It separately verifies that the
official new defaults differ for this geometry and that an explicit split
`disp2=42`, `disp3=48` combined result and first derivative equal the sum of
the corresponding official kernels. The geometry is away from either cutoff
discontinuity. This records the compatibility semantics rather than
silently conflating the new defaults with the older shared limit.

## Zero and trainable `s9`

The official combined dispersion wrapper skips ATM work when the value of
`s9` is zero. The local adapter retains the two-body and three-body physics
from the released kernels while avoiding a tensor-value Python branch. A
literal Python zero can skip ATM evaluation; tensor-valued zero still keeps
the graph connected. The regression distinguishes Python zero, ordinary
zero tensor, differentiable zero tensor, positive and negative differentiable
values, forward/reverse derivatives, mixed position/parameter response, and
vmap lanes. It checks the trainable-zero derivative against central finite
differences and keeps zero ATM energy semantics.
