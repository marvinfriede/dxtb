## Dependency and distribution decision

Positive acceptance used only the official PyPI wheel
`tad-dftd3==0.7.0`, SHA-256
`44bb0ddec5fdce42f4c50f0f8270a52a996390a25db827ef2e370110bd1bde7e`, with
`tad-mctc==0.9.1`. The unreleased U2 candidate, private wheels, source
injection, and site-package edits were not used. Historical U1/U2 reports
remain archival evidence only.

The repository's accepted test/development installation policy is the
documented controlled install: install dxtb's pinned dependencies, then
install the official D3 distribution with `--no-deps`. The official wheel
metadata pins mctc 0.8.0, so ordinary resolver compatibility is not claimed
and `pip check` correctly reports this conflict. This is an accepted
distribution-policy limitation for this work package, not a numerical D3
defect or an E1.3/E6a blocker. The local shim is activated by importing dxtb
before importing `tad_dftd3`; direct import before dxtb raises ImportError for
the removed `tad_mctc.autograd.is_batched` name. The shim adds that alias only
when absent and maps it to the tested `is_vmapped` utility.
`pip check` also reports the previously known tad-dftd4 0.8.0 pins on older
mctc/multicharge, NumPy<2 metadata from tad-dftd4/tad-libcint with NumPy 2,
and the installed ASE optional matplotlib extra. None is represented as a
passing resolver check; the D3 and conformer tests exercise runtime behavior
under the documented controlled environment.

## E1 component decision

E1.1 remains accepted: the RepulsionAG shortcut is removed from the required
path and ordinary torch operations provide the value and derivative route.
Existing position, parameter, higher-order, JVP, and vmap controls remain in
the accepted test set. E1.2 remains accepted: CoulombMatrixAG is removed and
the plain-torch ES2 setup/evaluation path remains authoritative. No
E1-required dxtb-local custom derivative shortcut was added for D3; the
adapter delegates C6, two-body, and ATM numerical work to official
`tad_dftd3` operations. Other custom Functions used by legacy implicit
solver/eigensolver ownership are outside the E1.1/E1.2/E1.3 component scope.

E1.3 requirements were audited against the official-release implementation:

| Requirement | Evidence and result |
| --- | --- |
| D3 energy and atom-resolved parity | Existing H2O, CH4, mixed-element, active-ATM, padded-number, and conformer controls; local two-/three-body composition agrees with the official kernels at the documented shared 50-Bohr compatibility cutoff. |
| C6, coordination and reference weighting | Official C6/weighting code is called by both exact-System and legacy paths; padding and unequal conformer/atom dimensions are covered. |
| `jvp`, `jacfwd`, `vmap` and combined transforms | Public GFN1 System tests retain D3 and pass JVP/jacfwd, vmap, mapped gradients and mapped jacfwd; standalone AtomicC6 tests cover nested transform behavior. |
| Reverse and higher derivatives | Reverse position/parameter controls pass. The public D3-enabled GFN1 directional third derivative agrees with a five-point finite difference of second derivatives (absolute error `3.67e-11`, relative error `1.80e-11`). |
| Active D3 parameters | Model-owned `s6`, `s8`, `s9`, `a1`, and `a2` gradients are finite and mapped gradients agree with summed serial gradients. |
| Trainable `s9=0` | ATM energy remains zero at the value while its nonzero physical derivative is retained; reverse, forward, mixed position/s9, vmap, and central finite-difference checks pass. |
| Positive, negative, and constant-zero `s9` | Value semantics and transform behavior are covered; literal Python zero skips ATM work, while tensor zero remains graph-capable. |
| Legacy component parity and options | Both exact-System and legacy entrypoints use the shared adapter. `chunk_size=None` is quiet; non-None values warn and are not silently applied. Captured references and setup remain unmutated across repeated calls. |
| Cutoffs and parameter forwarding | CN and dispersion cutoffs retain the dxtb legacy contract. Custom split two-/three-body cutoffs are compared at the official kernel boundary; defaults are not substituted for configured values. |

The `tad_mctc` shim was tested with ordinary evaluation, vmap, JVP, jacfwd,
nested reverse differentiation, `vmap(jacrev(...))`, and `vmap(jacfwd(...))`.
The official C6 implementation passed the padded-number and distinct
conformer-count cases. Optional `torch.compile(backend="eager")` passed; the
Inductor backend was not part of this acceptance. No production D3 defect
was found in the final audit.

**Decision A — E1.3: COMPLETE.** The original numerical and derivative
criteria pass with the official release under the accepted controlled
installation policy. The known wheel metadata mismatch remains documented as
a distribution limitation; ordinary pip resolution is not claimed.

**Decision B — E1: COMPLETE.** E1.1, E1.2 and E1.3 are accepted, and no
formerly passing E1 component regressed in the focused acceptance matrix.

## E6a public conformer acceptance

The acceptance call is the public
`torch.func.vmap(system.singlepoint, in_dims=(0,))(positions_batch)` using
independently built production ParamModule/Model/Model.setup Systems, the
PyTorch integral backend, the existing Result and SCFStatus types, and
default `out_dims=0`. The work maps geometries of one fixed System; it does
not stack different Systems.

The completed E6a.0–E6a.4 evidence covers:

- GFN1 and GFN2 H2/H2O, plus GFN1 CH4 and active-halogen Br2/NH3; three-lane
  conformer sets include batch sizes different from atom counts.
- Supported linear and Anderson mixing, charge/potential/Fock SCP controls,
  zero and finite temperature, positive fixed trips, and `maxiter=0`.
- Complete serial/mapped registered Result-tree parity: field order and
  pytree spec, shape, dtype/device/value, optional `None`, classical labels
  and ordering, charges, potential, density, orbitals, integrals, multipoles,
  convergence, iterations, residual, and public SCFStatus.
- Public D3-enabled GFN1 JVP, jacfwd, jacrev, vmap, mapped gradients, and
  D3 parameter gradients; full GFN2 with its default D4, ES2, ES3, AES2 and
  D4SC components has value, status, and derivative coverage.
- Repulsion, D3, classical D4, Halogen, ES2, ES3, AES2, D4SC, explicit ALPB,
  ElectricField, and ElectricFieldGrad in their supported configurations.
  Component-specific standalone evidence is not substituted for the public
  integration tests documented in E6a.3/E6a.4.
- Position-gradient parity, Model-owned parameter-gradient connectivity,
  Hessian finite-difference accuracy, public D3 third-directional accuracy,
  and zero cross-conformer Jacobian blocks. Result/status failure semantics
  remain those accepted in E6a.2.
- Calculator eager stopping, warning/error behavior, legacy fallback, and
  parameter ownership controls remain separate and passing.

GFN0 IES/SRB whole-System vmap, arbitrary custom callbacks, mixed-System
batching, whole-System libcint transforms, CUDA numerical execution, E7
padding safety, and E4.6 compatibility retirement are outside the binding
E6a contract. Public GFN0 spin validation remains covered. Unreachable status
categories continue to use the separately accepted projection tests rather
than fabricated public failures.

**Decision C — E6a: COMPLETE.** The original mandatory GFN1/GFN2 PyTorch
public conformer, Result, status, component, and derivative boundary is met;
the exclusions above are separately owned features rather than missing E6a
acceptance rows.
