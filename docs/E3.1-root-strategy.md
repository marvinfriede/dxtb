# E3.1 physical-root differentiation strategy

Status: **E3.1a, E3.1s, and E3.1b complete.** This document retains the E3.1a
reference evidence and records the accepted implicit-root implementation.

## Mathematical target

The reference suite uses the existing E4core raw map for each configured
representation:

```text
charge:     G(x,p) = scf_map(x, inputs(p)).mapped_x
potential:  G(x,p) = potential_map(x, inputs(p), layout).mapped_x
Fock:       G(x,p) = fock_map(x, inputs(p)).mapped_x

F(x,p) = G(x,p) - x = 0
```

`SCFMapResult` contains the physical map outputs only. Mixer histories, damping,
iteration counts, active masks, convergence selection, and finalization are
outside `F`. The finite-tolerance physical state `root_x` is the exact map
input on which the solver tested convergence. The selected `map_result` is
`G(root_x)`, and the recorded residual is `map_result.mapped_x - root_x`; the
outcome retains both values. It does not promote `map_result.mapped_x` to the
root or perform an extra raw-map call to reconstruct the tested residual.
Potential-mode public finalization is evaluated only after root acquisition.
The charge, potential, and Fock tests use their existing maps and verify the
raw result has no solver-history or finalization fields.

The focused executable reference suite is
`test/test_scf/test_functional_root_derivatives.py`. Its root helper receives
`x_atol` and `x_atol_max` explicitly, records the convergence-tested root,
paired selected map result, `G(root_x)-root_x` residual, physical solver map
count, convergence status, electronic energy, and finalized energy, and does
not inspect `requires_grad` or grad mode to choose tolerance. Instrumented
tests show that the eager solver's accepted candidate uses the retained root
input, its exact residual drives convergence, and no later physical map runs.
Any extra map calls in Jacobian or FD probes are reference evaluations and
are not included in the primal solver count.
Derivative probes explicitly force one Lorentzian spectral branch for reverse
and forward-mode comparisons. Direct physical finite differences use fresh
Calculator/System evaluations; they are not finite differences of a lower
autograd derivative.

## Executable findings

The GFN2/NO2 potential-mode reference uses the open-shell doublet, finite
temperature, the existing functional PyTorch route, and a 300-map cap. The cap
is not reached: the `1e-14` reference converges in 32 maps. The independent
physical FD plateau and tblite values remain about `-3.35277` for the selected
hyperpolarizability component and `+0.7977` for `pol_deriv`.

| `x_atol = x_atol_max` | Hyper maps / residual max | Nested `d³E/dFᵧ³` | Mixed response maps / nested `pol_deriv` | Interpretation |
|---:|---:|---:|---:|---|
| `1e-10` | 20 / `5.55e-11` | about `+0.022` | 20 / about `1.1501` | Ordinary SCF convergence does not make the third response physical. |
| `1e-12` | 24 / `3.78e-13` | `-3.3525797` | 24 / about `0.79776` | Both responses enter the independent physical-FD comparison bounds. |
| `1e-13` | 25 / `9.33e-14` | `-3.3527583` | tight-root response remains in the physical-FD interval | Stable higher-order reference. |
| `1e-14` | 32 / `1.41e-15` | `-3.3527704` | — | Hyper response changes only slightly; stopping counts become stencil-sensitive. |

The test also evaluates the response at `1e-11`, records first/second/third
derivatives and energy changes between adjacent roots, and compares the
hyperpolarizability and mixed response directly with the independent physical
FD ranges. Existing T0.2 settings and markers remain unchanged. A smooth
closed-shell H2 control at both zero and 300 K records root residual, map
count, energy, first and second field response over `1e-10`, `1e-12`, and
`1e-13`; both agree with a fresh-root direct-energy FD. The finite-temperature
H2 and open-shell NO2 cases also extend the Jacobian reference beyond the
smooth zero-temperature control.

The dense first-order reference explicitly computes `Jx = dG/dx` and
`Jp = dG/dp` at the convergence-tested `root_x`, then solves:

```text
(I - Jx) dx/dp = Jp
```

using ordinary `torch.func.jacrev`, `torch.func.jvp`, and `torch.linalg.solve`.
The reference covers H2/GFN1 charge, potential, and Fock modes; finite-
temperature H2/GFN1 charge mode; and the required NO2/GFN2 300 K potential
mode. For every row, the dense response agrees with fixed-trip functional
unrolling and a fresh physical-energy finite difference at the same explicit
root tolerance. Each row applies its existing representation finalization:
charge-mode final charges, potential-mode extra spectrum, or Fock-mode final
spectrum. This is test-only code; it does not define a production adjoint.

For H2/GFN1 at a `1e-12` root tolerance, Simple and Anderson reach matching
root states, density, occupation, orbital energies, and energy. Their first
and second field responses also agree within the test bounds. NO2 remains the
Anderson endpoint case. Iteration counts and mixer histories are not compared
as physical quantities.

The NO2 and H2 tests retain per-tolerance root and derivative-change records
in pytest output. Acceptance commands are listed below. The tests assert the
physical-FD comparisons, response stabilization at tighter roots,
root-residual criteria, mixer agreement, and the dense Jacobian equation; no
conclusion depends on diagnostic print output.

## Root accuracy and fail-closed preparation

An SCF energy/charge convergence status alone is insufficient evidence for a
high-order derivative. The NO2 reference evidence shows that `1e-10` is
inadequate for its third response, `1e-12` enters the current direct-FD bounds,
and `1e-13` gives a more stable reference. The implementation uses the
configured `x_atol` and `x_atol_max` explicitly; users and tests select any
tighter target. It does not choose a tolerance from `requires_grad`,
`torch.is_grad_enabled`, or transform mode, and the evidence does not justify
a universal public tolerance change.

An implicit request acquires and validates the primal eagerly. A
nonconverged outer root, invalid Fermi trajectory/final spectrum, or
`maxiter=0` raises `SCFConvergenceError` before root attachment. The private
prepared-root response then receives only validated root and explicit tensor
inputs and performs no convergence/status inspection or SCF iteration inside
transforms. An invalid physical root raises before attachment; it does not
produce a NaN, detached, zero-gradient, or unrolled fallback. `maxiter=0`
compatibility remains separate for ordinary legacy SCF behavior. Reported
iterations and status describe only the primal SCF trajectory. A distinct
failure of the matrix-free tangent/adjoint solve is retained as tensor
diagnostics; its unconverged iterate is replaced by NaNs in the derivative
path, so it cannot masquerade as a valid implicit response, including under
`vmap`. `LinearSolveResult.converged` is the tensor status; eager reverse
gradients receive NaNs, JVP/jacfwd tangents receive NaNs, and a failed vmap
lane is NaN-masked while successful lanes retain their own finite results.
There is no finite partial-iterate fallback.

## Current E3.1b implementation boundary

E3.1s is dxtb-local and complete. The canonical spectral matrix has 24 passing
checks. Physical density and equal/atomic free-energy corrections use the
invariant matrix-function paths with one authoritative Fermi state;
`storch.eighb` supplies reporting/filling-forward eigensystem values. The
historical `requires_grad` spectral split and coefficient-gauge free-energy
path have been removed.

E3.1b's primal is the functional solver's retained `root_x`, paired with the
selected `G(root_x)` map result and its residual. The new prepared-root
boundary checks outer and Fermi convergence before differentiation and rejects
`maxiter=0`. The transform operation takes an explicit floating tensor tree
from `SCFInputs` and the raw representation map. It owns only `x*(p)`;
charge/potential/Fock finalization and invariant free energy remain ordinary
composition after attachment. Eligible single-System `scf_mode="implicit"`
uses this route; batches, unsupported interactions, and legacy overrides keep
the legacy compatibility path. The global/default Broyden setting also stays
on the legacy implicit engine, which historically owns that mode and ignores
`ConfigSCF.mixer`; explicit Simple or Anderson selects the new functional
route. `strict` is FULL-specific and does not convert implicit Broyden into a
FULL-style error or Anderson warning. Negative temperature/Fermi iteration
settings, missing functional integrals, non-single-System shapes, and any
legacy engine `args`/`kwargs` retain legacy routing. Whole-System `vmap`
remains E6a scope.

The matrix-free tangent and adjoint equations are respectively
`(I - Jx) xdot = Jp pdot` and `(I - Jx)^T lambda = v`. A fixed-trip
BiCGSTAB implementation provides tensor diagnostics and avoids materializing
the full root Jacobian. Its relative convergence threshold is
`max(configured_rtol, 10 * finfo(dtype).eps)`, so float64 keeps its established
threshold while float32 is not rejected for residuals below its roundoff
scale. Dense Jacobian solves remain test oracles. The legacy `scf/implicit`
implementation remains in the tree pending a complete consumer audit and
compatibility gate.

The implicit route supplies physical-root semantics and transform-compatible
higher derivatives, but is not currently a performance win for the measured
NO2 third-order case: isolated implicit execution took 89.81 s / 5.22 GB peak
RSS, compared with 20.45 s / 3.04 GB for tight unrolling. This is measured
performance debt for a later package; the root trajectory is detached and the
implicit route does not retain the unrolled SCF trajectory. No stored T0.2
references, NO2 markers, SCF tolerances, or canonical spectral status entries
were changed.

The new suite covers the transform primitive, matrix-free linear-solve oracle,
explicit non-leaf inputs, all three raw representations, H2 dense IFT/FD
references, mixer agreement, geometry and mixed responses, free-energy
finalization, and fail-closed primal preparation. The slow NO2 potential
case compares the implicit response against dense IFT, tight unrolling, and
independent physical finite differences. The existing NO2 historical
reference selection remains 8 passed with 2 expected XFAILs; no stored
reference or marker changed.

The float32 correction was validated in all five supported environments. Two
earlier xdist executions of the slow NO2 row passed the first-order dense-IFT
and unrolled comparisons but returned NaN at the third-order comparison; the
serial run passed. A bounded follow-up ran that exact row in three fresh
serial processes, three fresh `pytest -n 1` workers, and three batches of two
concurrent fresh processes. All twelve executions passed, including the
third-order comparison. Every process constrained
`OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, and
`NUMEXPR_NUM_THREADS` to one, and set PyTorch intra-op and inter-op thread
counts to one before the test. This differs from the earlier run setup, which
set only `OMP_NUM_THREADS=1`.

Temporary instrumentation recorded five float64 matrix-free solves in each
execution. All returned finite solutions and `converged=True`; no solve
missed its residual target. Iteration counts varied modestly (typically
`[8, 1, 1, 6, 6–8]`), while the largest observed residual/target ratio was
about `0.86`. The earlier discrepancy did not reproduce under fully
constrained worker or concurrent execution, and the recorded solves provide
no evidence that the fail-closed linear-solve boundary was crossed. It is
classified as a slow-test numerical thread-pool isolation issue; no
production solver change or tolerance adjustment was made. During the paired
runs the host reported about 488 GiB available memory and 49 GiB swap, with
no observed OOM kill, allocation failure, or swap pressure.

E3.1b is accepted and closed. The dtype-aware change leaves the float64
convergence threshold unchanged, and this bounded diagnosis does not justify
changing the accepted root or linear-solver architecture.

Paired runtime characterization under PyTorch 2.14.1 CPU measured the test
process containing both the implicit path and its tight-unrolled reference.
The H2 second/third-response comparison passed in 9.06 s with 537,324 KB peak
RSS. The paired NO2 comparison passed in 203.48 s with 6,982,928 KB peak RSS.
Separate fresh-process attribution on the same NO2 potential third response
measured the implicit-only path at 89.81 s / 5,220,600 KB peak RSS and the
tight-unrolled-only reference at 20.45 s / 3,041,312 KB. The implicit path
therefore costs more in this high-order case, but the retained primal SCF
trajectory is detached before attachment; its memory does not include an
unrolled trajectory. The additional cost comes from differentiating through
the fixed-trip matrix-free tangent/adjoint solves and invariant spectral
response. The historical NO2/GFN2 reference selection took 506.32 s with
66,246,932 KB peak RSS under its logical-worker run. These measurements are a
runtime baseline, not speed thresholds.

The implementation changes production runtime routing for explicitly
requested eligible single-System `scf_mode="implicit"`; FULL routing and
legacy compatibility cases remain unchanged. Linear-solve diagnostics and
the invalid-solve transform behavior are covered by the focused suite.
