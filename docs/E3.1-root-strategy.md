# E3.1 physical-root differentiation strategy

Status: **E3.1a reference gate complete; no implicit derivative primitive
added.** E3.1s spectral acceptance must precede E3.1b production transform
acceptance.

## Mathematical target

The reference suite uses the existing E4core raw map for each configured
representation:

```text
charge:     G(x,p) = scf_map(x, inputs(p)).mapped_x
potential:  G(x,p) = potential_map(x, inputs(p), layout).mapped_x
Fock:       G(x,p) = fock_map(x, inputs(p)).mapped_x

F(x,p) = G(x,p) - x = 0
```

`SCFMapResult` contains the physical map outputs only. Mixer histories, damping,
iteration counts, active masks, convergence selection, and finalization are
outside `F`. The finite-tolerance physical state `root_x` is the exact map
input on which the solver tested convergence. The selected `map_result` is
`G(root_x)`, and the recorded residual is `map_result.mapped_x - root_x`; the
outcome retains both values. It does not promote `map_result.mapped_x` to the
root or perform an extra raw-map call to reconstruct the tested residual.
Potential-mode public finalization is evaluated only after root acquisition.
The charge, potential, and Fock tests use their existing maps and verify the
raw result has no solver-history or finalization fields.

The focused executable reference suite is
`test/test_scf/test_functional_root_derivatives.py`. Its root helper receives
`x_atol` and `x_atol_max` explicitly, records the convergence-tested root,
paired selected map result, `G(root_x)-root_x` residual, physical solver map
count, convergence status, electronic energy, and finalized energy, and does
not inspect `requires_grad` or grad mode to choose tolerance. Instrumented
tests show that the eager solver's accepted candidate uses the retained root
input, its exact residual drives convergence, and no later physical map runs.
Any extra map calls in Jacobian or FD probes are reference evaluations and
are not included in the primal solver count.
Derivative probes explicitly force one Lorentzian spectral branch for reverse
and forward-mode comparisons. Direct physical finite differences use fresh
Calculator/System evaluations; they are not finite differences of a lower
autograd derivative.

## Executable findings

The GFN2/NO2 potential-mode reference uses the open-shell doublet, finite
temperature, the existing functional PyTorch route, and a 300-map cap. The cap
is not reached: the `1e-14` reference converges in 32 maps. The independent
physical FD plateau and tblite values remain about `-3.35277` for the selected
hyperpolarizability component and `+0.7977` for `pol_deriv`.

| `x_atol = x_atol_max` | Hyper maps / residual max | Nested `d³E/dFᵧ³` | Mixed response maps / nested `pol_deriv` | Interpretation |
|---:|---:|---:|---:|---|
| `1e-10` | 20 / `5.55e-11` | about `+0.022` | 20 / about `1.1501` | Ordinary SCF convergence does not make the third response physical. |
| `1e-12` | 24 / `3.78e-13` | `-3.3525797` | 24 / about `0.79776` | Both responses enter the independent physical-FD comparison bounds. |
| `1e-13` | 25 / `9.33e-14` | `-3.3527583` | tight-root response remains in the physical-FD interval | Stable higher-order reference. |
| `1e-14` | 32 / `1.41e-15` | `-3.3527704` | — | Hyper response changes only slightly; stopping counts become stencil-sensitive. |

The test also evaluates the response at `1e-11`, records first/second/third
derivatives and energy changes between adjacent roots, and compares the
hyperpolarizability and mixed response directly with the independent physical
FD ranges. Existing T0.2 settings and markers remain unchanged. A smooth
closed-shell H2 control at both zero and 300 K records root residual, map
count, energy, first and second field response over `1e-10`, `1e-12`, and
`1e-13`; both agree with a fresh-root direct-energy FD. The finite-temperature
H2 and open-shell NO2 cases also extend the Jacobian reference beyond the
smooth zero-temperature control.

The dense first-order reference explicitly computes `Jx = dG/dx` and
`Jp = dG/dp` at the convergence-tested `root_x`, then solves:

```text
(I - Jx) dx/dp = Jp
```

using ordinary `torch.func.jacrev`, `torch.func.jvp`, and `torch.linalg.solve`.
The reference covers H2/GFN1 charge, potential, and Fock modes; finite-
temperature H2/GFN1 charge mode; and the required NO2/GFN2 300 K potential
mode. For every row, the dense response agrees with fixed-trip functional
unrolling and a fresh physical-energy finite difference at the same explicit
root tolerance. Each row applies its existing representation finalization:
charge-mode final charges, potential-mode extra spectrum, or Fock-mode final
spectrum. This is test-only code; it does not define a production adjoint.

For H2/GFN1 at a `1e-12` root tolerance, Simple and Anderson reach matching
root states, density, occupation, orbital energies, and energy. Their first
and second field responses also agree within the test bounds. NO2 remains the
Anderson endpoint case. Iteration counts and mixer histories are not compared
as physical quantities.

The NO2 and H2 tests retain per-tolerance root and derivative-change records
in pytest output. Acceptance commands are listed below. The tests assert the
physical-FD comparisons, response stabilization at tighter roots,
root-residual criteria, mixer agreement, and the dense Jacobian equation; no
conclusion depends on diagnostic print output.

## Proposed root accuracy and failure contract

An SCF energy/charge convergence status alone is insufficient evidence for a
high-order derivative. E3.1b should require an explicit derivative-root
accuracy setting, independent of AD mode, and validate both raw residual
criteria from the E0 contract at the selected root. The reference evidence
shows that `1e-10` is inadequate for the NO2 third response, `1e-12` enters the
current direct-FD bounds, and `1e-13` gives a more stable reference. It does
not justify a single new public tolerance for every method, representation,
temperature, or derivative order. E3.1b must keep the derivative-root target
explicit and must not infer it from `requires_grad`, `torch.is_grad_enabled`,
or transform mode.

The required nonconverged-root semantics are fail-closed, with no derivative
sentinel. A physical-root derivative request is explicit in API/configuration;
AD mode never switches solver tolerance or behavior. In eager public
execution, such a request raises `SCFConvergenceError` on a nonconverged
primal regardless of legacy warning/return behavior for ordinary FULL calls.
For transformed requests, a nonconverged root must never produce a derivative
presented as a physical-root derivative; no NaN, detached, zero-gradient, or
silent unrolled fallback is acceptable. E3.1b must specify and test the
transform-safe enforcement boundary. The current executable test only
characterizes a host-side status preflight before a callback; it does not
demonstrate composition with reverse, JVP, jacfwd, nested differentiation, or
vmap. `maxiter=0` retains its one-shot compatibility meaning and is never
accepted by the root-derivative API. Iteration/status reporting describes
only the actual primal trajectory.

## Selected implementation direction

**Outcome B: implement a new transform-compatible implicit derivative only
after the E3.1s spectral prerequisite is accepted.** Functional unrolling remains the
correctness/reference path. The measured NO2 response depends strongly on
finite trajectory/root accuracy, while E0 defines the physical derivative by
`G(x,p)-x=0`, not by differentiating Anderson history. The dense Jacobian
reference reproduces the first physical response without mixer history. A
fixed-trip unroll is therefore retained as the test oracle, but it is not the
production high-order attachment strategy.

E3.1b must specify and test before merge:

1. primal acquisition by the existing functional solver and the explicit
   derivative-root accuracy target;
2. the exact `F(x,p)=G(x,p)-x` interface for charge, potential, and Fock modes;
3. reverse solve `(I-Jx)^T λ = dL/dx` and tangent solve
   `(I-Jx) dx/dp = Jp`;
4. differentiability of both solves for nested orders, JVP, jacfwd, and vmap;
5. fail-closed nonconverged behavior and separate `maxiter=0` compatibility;
6. an implicit root boundary that returns `x*` only; existing differentiable
   representation-specific finalization remains ordinary composition outside
   the primitive, with truthful status/iteration values;
7. padding/batching behavior and comparisons against tight unrolled and
   independent physical-FD references;
8. the internal root-acquisition boundary that exposes the exact
   convergence-tested `root_x`, its selected `G(root_x)` result, and status.
   The current public `SCFSolveResult` does not carry `root_x`; do not
   reconstruct it from `map_result.mapped_x` or add it to public `Result`
   solely for implicit differentiation. Keep representation-specific
   finalization outside the implicit root boundary.

No custom `torch.autograd.Function`, VJP, JVP, adjoint primitive, or graph
introspection was added in this strategy gate. The corrected package order is:

```text
E3.1a root-state/reference correction
    -> E3.1s upstream invariant spectral/density prerequisite
    -> E3.1b transform-compatible implicit-root implementation
```

Root-solver-only scaffolding may be reviewed separately, but it cannot be
called transform-complete or routed to production before E3.1s.

## Separate spectral prerequisite

The pinned dependency is `tad-mctc==0.9.1`. Its `storch.eighb` exposes
conditional/Lorentzian broadening around eigenvector derivatives; the
`_SymEigBroad_V2` primitive provides setup-context, JVP, and vmap support, but
the derivative uses a broadened eigenvalue-gap denominator. That is not an
invariant divided-difference/matrix-function contract at exact degeneracy and
is already insufficient for the canonical E0 higher-order/small-gap targets.
The existing component selection remains 8 passes and 16 expected XFAILs:

| Target | Current expected status |
|---|---|
| `eigensolver.degenerate_aufbau` | orders 2–3 XFAIL; order 1, forward, JVP, vmap pass |
| `eigensolver.degenerate_fermi` | orders 2–3 and vmap XFAIL; order 1, forward, JVP pass |
| `eigensolver.small_gap_aufbau` | orders 1–3, forward, JVP XFAIL; vmap passes |
| `eigensolver.small_gap_fermi` | orders 1–3, forward, JVP, vmap XFAIL |

**Decision: a narrowly scoped upstream tad-mctc prerequisite is required.**
It should add a gauge-invariant Frechet/divided-difference derivative for the
density/matrix function, including generalized overlap handling, with reverse
orders 1–3, JVP, jacfwd, vmap, and density/energy comparisons for equal-
occupation exact degeneracy, finite-temperature degeneracy at the chemical
potential, continuous small nonzero gaps, zero-temperature internal occupied
degeneracy, and a nonzero occupied/unoccupied zero-temperature gap. dxtb
should consume that primitive only after its upstream acceptance is complete;
do not replace it with a local custom eigensolver derivative or broadening
factor tuning. This spectral obligation is independent of the NO2 finite-root
response and does not revise E3.0's localization.
